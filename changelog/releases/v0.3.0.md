# Context Vigilance Kit v0.3.0: Survey, Looser Versions, Any Link Form, and Mobile Apps

## Why Care?

v0.2.0 made the practice installable. A month of using it across our own repos showed where it was too strict and where it was missing a view of the whole. This release bends the rules to fit repos as they are (any version format, any link form), adds a way to see every `context-v/` folder at once, and adds the first skill aimed at someone who isn't a developer.

## What's New?

### Highlights

- **Survey.** `/cv:survey` builds a dashboard of every `context-v/` folder in scope: what's in flight, what's stuck, what's a stub, and who's moving. One picker narrows it to a repo and everything under it. See the [live examples](https://context-v.dev/survey/).
- **Ship a web app to phones.** The new `mobile-x-platform-w-tauri` skill walks a non-developer owner through wrapping a hosted web app in a Tauri 2 shell for iPhone and Android, testing it on a real phone, delivering it through TestFlight and Google Play, and keeping it working. It writes the owner a step-by-step guide and never uploads a build without their yes.

### Changed

- **Versions can have three parts or four.** Market-standard `0.1.0` is as valid as `0.0.0.1`, and Epoch SemVer (`1002.3.0`) works too. Agents count the parts before reading the digits, and the user picks the format.
- **Every link form works.** Obsidian wikilinks with or without `.md`, and ordinary Markdown links, are all valid. Nothing needs converting, and a resolver shows where each link lands.
- **Ledes are plain text.** Cards and previews show a lede raw, so the kit now says no backticks, asterisks or links in it.

## Upgrade

In Claude Code, run `/cv:upgrade` (or `/plugin update cv@context-vigilance-kit`), then start a new session so new skills load. Nothing in an existing `context-v/` has to change.

## What's Next?

- `docs-v/`: docs on the same system as `context-v/`, with agents keeping them current.
